# Service Taxi Reservation System (STSRS)

## نظرة عامة
- نظام حجز وإدارة سيارات الخدمة في فلسطين.
- الواجهة الخلفية مبنية على `Node.js + Express` وتتصل بقاعدة بيانات Supabase (PostgreSQL).
- تدير مصادقة المستخدمين، السائقين، الرحلات، الحجوزات، المدفوعات، المحافظ، والمهام المجدولة.
- واجهة Flutter (داخل مجلد `frontend/`) تستهلك واجهات `/api`.

## المعمارية والتدفق
- **HTTP Layer**: الطلبات تمر عبر `server.js`، تطبق CORS، Middleware الترجمة `i18n`, معدل الطلبات، ثم توجّه إلى الراوتر المناسب تحت `/api/*`.
- **Controllers**: منسقة داخل `controllers/`، كل Controller يتعامل مع نموذج واحد ويعتمد على خدمات مساعدة في `services/` و `utils/`.
- **Models**: ملفات `models/*.js` تغلف استعلامات Supabase وتجريد قواعد البيانات.
- **Jobs**: ملفات `jobs/*.js` تشغل Cron (باستخدام `node-cron`) لفتح الرحلات، التحقق من الانطلاق، متابعة المتخلفين، وإنشاء رحلات يومية.
- **Middleware**: مصادقة JWT، تفويض الأدوار، معالجة الأخطاء العالمية، والمحدد الزمني للطلبات.

## دورة حياة الطلب
1. العميل يرسل طلبًا إلى `/api/...`.
2. Middleware يتحقق من رأس التفويض، اللغة، وحدود المعدل.
3. الراوتر يربط الطلب بالـ Controller المناسب.
4. الـ Controller يستدعي النموذج أو الخدمة، ويكتب/يقرأ من Supabase.
5. الاستجابة تعاد بالتنسيق القياسي (JSON موحد + رسائل مترجمة).

## المكونات الأساسية
- `authController`: تسجيل/تسجيل دخول، إعادة تعيين كلمة المرور، إدارة الجلسات، JWT.
- `driverController` و `vehicleController`: إدارة بيانات السائق والمركبة.
- `lineController` و `tripController`: تعريف الخطوط، إنشاء الرحلات اليومية، تحديث الحالات.
- `reservationController`: حجوزات الركاب، إدارة المقاعد، قوائم الانتظار.
- `paymentController` و `walletController`: عمليات PalPay/JawwalPay الافتراضية، تحويلات المحافظ، إنشاء سجلات `Payment`.
- `ratingController`: تقييمات الرحلات بعد الانتهاء، تجميع درجات السائق.
- `scheduleController`: قوالب الجداول اليومية.
- `adminController`: صلاحيات متقدمة، مراقبة الحالة، تفعيل الحسابات.

## المهام الخلفية (Jobs)
- `tripOpeningJob`: يفتح الرحلات تلقائيًا قبل موعدها المحدد ويحدّث حالتها.
- `departureCheckJob`: يتحقق من انطلاق الرحلات في الوقت المحدد ويرصد التأخيرات.
- `noShowCheckJob`: يحدد الركاب الذين لم يحضروا ويتعامل مع المقاعد المحجوزة.
- `dailyTripCreationJob`: ينشئ رحلات جديدة بناءً على قوالب الجداول لليوم التالي.
> تبدأ جميع المهام بعد التأكد من نجاح الاتصال بقاعدة البيانات أثناء تشغيل الخادم.

## المتطلبات المسبقة
- Node.js 18+ و npm.
- حساب Supabase (URL + Key)، وقاعدة بيانات تحتوي على الجداول المذكورة في مجلد `migrations/`.
- متغيرات البيئة (انظر `.env.example` إذا كان متوفرًا، أو أضف ملف `.env` جديد يتضمن على الأقل):
  ```
  PORT=3000
  NODE_ENV=development
  SUPABASE_URL=...
  SUPABASE_KEY=...
  JWT_SECRET=...
  JWT_ACCESS_EXPIRY=1d
  EMAIL_HOST=...
  EMAIL_PORT=587
  EMAIL_USER=...
  EMAIL_PASS=...
  PALPAY_API_KEY=...
  JAWWAL_PAY_API_KEY=...
  PASSWORD_RESET_URL_BASE=https://frontend/reset-password
  CORS_ORIGIN=http://localhost:3000
  ```

## تشغيل الخادم
1. تثبيت الاعتمادات:
   ```bash
   npm install
   ```
2. تشغيل التطوير:
   ```bash
   npm run dev
   ```
3. تشغيل الإنتاج:
   ```bash
   npm run start
   ```

## فحص الصحة والوثائق
- `GET /health`: يتأكد من حالة الخادم وقاعدة البيانات.
- `GET /api/db/test`: يجرّب Supabase ويرجع معلومات الخطأ إن وجدت.
- `GET /api/docs`: يعرض Swagger UI المبني من `docs/swagger.js` ويحتوي على تعريفات جميع المسارات.

## تكامل الواجهة الأمامية
- واجهة Flutter داخل `frontend/` تتبع خطوات التكامل الموضحة في `BACKEND_FRONTEND_INTEGRATION.md`.
- تأكد أن قيمة `CORS_ORIGIN` تشمل نطاق تطبيق Flutter (أثناء التطوير: `http://localhost:PORT`).
- استخدم مسارات `auth` للحصول على JWT، ثم مرر التوكن في `Authorization: Bearer <token>`.

## إدارة البيانات
- المجلد `migrations/` يحتوي على سكربتات SQL لبناء الجداول (خطوط، رحلات، حجوزات، تقييمات...).
- `models/*.js` تغطي CRUD القياسي؛ يمكن استخدام Supabase مباشرة عند الحاجة لكن يفضل المرور عبر هذه الطبقة للمحافظة على التحقق المركزي.
- `utils/` يتضمن مساعدة للمصادقة، الرسائل البريدية، حساب المقاعد، التحقق من المدخلات، والسجلات (`logger.js`).

## إستكشاف الأخطاء وإصلاحها
- التحقق من السجلات في الطرفية: يستخدم النظام `utils/logger.js` لعرض حالات التشغيل والاتصال.
- إذا فشل الاتصال بـ Supabase، سيتم تسجيل تحذير ولن تبدأ المهام الخلفية.
- تأكد من صحة توقيت السيرفر لأن المهام المجدولة تعتمد على التوقيت المحلي.
